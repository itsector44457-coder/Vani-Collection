# Vani Collection — Requirements from Rishabh ERP (Ujjain) Vendor

> **Purpose:** Connect the Vani Collection e-commerce website with the shop's Rishabh ERP
> (billing + inventory), so that (a) item, price and stock flow from ERP to the website, and
> (b) confirmed website orders flow into the ERP as sales vouchers.
> **Status on our side:** The website backend connector is **already built and tested** against a
> mock ERP (`backend/scripts/mock-erp-server.js`, `backend/tests/erp-connector.test.js`). Only the
> vendor's exact API paths, field names and authentication need to be filled in — see
> `docs/RISHABH-ERP-INTEGRATION.md` for the technical contract. This document lists exactly what we
> need from the vendor to switch it on.
> **Security note:** Please **do not send passwords/tokens on WhatsApp or in plain chat**. Credentials
> will be stored only in the production server's `.env` file, through a channel we agree on.

---

## 1. Data flow we need

| # | Direction | Data | Frequency |
| --- | --- | --- | --- |
| 1 | ERP → Website | Item master: item code, barcode, size, colour, MRP, sale rate, HSN, GST % | On change / daily |
| 2 | ERP → Website | Closing stock per item code, per godown/location | Every 15 min (polling) or push webhook |
| 3 | ERP → Website | Price changes (MRP / sale rate) | On change |
| 4 | Website → ERP | Confirmed order → sales voucher (customer, items, totals, GST, payment mode) | On every confirmed order |
| 5 | ERP → Website | Order/voucher status: voucher no., packed / shipped / cancelled | On change |

Product photos, descriptions and website offers are managed on the website admin — the ERP is
**not** expected to supply images (please confirm if item images exist in the ERP).

## 2. Questions — please answer each in writing

### A. API availability & hosting
1. Does the ERP expose a **REST (JSON) or SOAP (XML) API**? If not, what is available —
   read-only SQL database access, or scheduled CSV/Excel export/import?
2. Is the ERP hosted on the **shop's local computer** or on **cloud/internet**? If local, how will
   our cloud server reach it (static public IP, cloud version, or a small sync agent on the shop PC)?
3. API **base URL** for test and production, plus API documentation (PDF/link/Postman collection).
4. **Authentication:** API key / bearer token / Basic auth / IP allow-list? If token-based, what is
   the token lifetime and how is it refreshed?
5. Is a **staging/test company** (dummy firm) available for UAT before go-live?
6. Rate limits, maintenance windows, and do you need to **whitelist our server IP**?
7. Is API access a **paid module**? If yes, please share a written quotation (one-time vs yearly,
   what is included) and the delivery timeline.

### B. Item master, price & stock
8. Item master fields available: item code, barcode, size, colour, MRP, sale rate, HSN, GST %,
   unit, active/inactive flag. Please share **one sample response**.
9. What is the unique key per size/colour — item code or barcode? Our website keys every variant
   by a unique SKU (e.g. `VC-AN-01-M`), so we need a one-time mapping sheet if codes differ.
10. Stock response: is quantity available **per godown/location**? Please list all location/godown
    codes (store, godown) and confirm which location online orders should deduct from.
11. Can item/stock APIs return **only records changed since a timestamp** (delta sync) and support
    **pagination**? If not, full-list polling every 15 minutes is acceptable to us.
12. Are MRP/sale rates **GST-inclusive or exclusive**? Who is the master of online price — if the
    ERP sale rate changes, should the website price change automatically?

### C. Orders, invoicing & returns
13. Sample payload to create a **sales voucher/order** from an external order number, and the
    response (voucher number). Do you support an **idempotency/duplicate check** on our external
    order number, so a retried request never creates a double voucher?
14. **GST invoice ownership:** should the legal GST invoice be generated by the ERP (with a separate
    online series, if required) — our website can also generate one, but both must not run in
    parallel. Who signs off the series (client/CA)?
15. Online customers in the ERP: should each customer become a separate ledger/debtor, or should
    all website orders book under one common "Online Customer" ledger?
16. Order cancellation, return and refund: how should these reflect in the ERP — sales return /
    credit note? Is there an API/status for that?
17. Dispatch details: is there a field for courier name / LR-AWB number on the voucher, if dispatch
    is recorded in the ERP?
18. Does the ERP support **outbound webhooks** (HTTP push to our server) for stock, price and order
    status? If not, polling from our side is fine — please just confirm.

## 3. What our connector already expects (adaptable)

Our paths, auth header and field names are configuration — **if your API already exists with
different paths/names, keep yours; we will adapt.** Reference contract:

```env
ERP_BASE_URL=<vendor base URL>
ERP_AUTH_HEADER=Authorization        # or x-api-key, as per vendor
ERP_AUTH_TOKEN=<token>               # server .env only
ERP_PRODUCTS_PATH=<item master path> # e.g. /api/items
ERP_STOCK_PATH=<stock path>          # e.g. /api/stock
ERP_ORDERS_PATH=<sales order path>   # e.g. /api/sales-order
```

**Order we will POST to the ERP** (header `Idempotency-Key: <orderNumber>`):

```json
{
  "externalOrderNo": "VC1712345678901",
  "orderDate": "2026-10-05T09:12:00.000Z",
  "customer": { "name": "…", "mobile": "…", "email": "…" },
  "shippingAddress": { "line1": "…", "city": "Ujjain", "state": "Madhya Pradesh", "pincode": "456010" },
  "items": [{ "sku": "VC-AN-01-M", "quantity": 1, "rate": 2499, "gstRate": 5 }],
  "totals": { "subtotal": 2499, "discount": 0, "shipping": 0, "tax": 119, "total": 2499, "currency": "INR" },
  "paymentMode": "razorpay"
}
```

**Webhooks you may POST to us** (optional; polling works without these) at
`POST https://<api-host>/api/integrations/erp/webhook`, signed with HMAC-SHA256 over the raw body
(header `x-erp-signature`, shared secret) and a unique `x-event-id` header per event:

```json
{ "type": "stock.update",  "items": [{ "sku": "VC-AN-01-M", "warehouseId": "PRIMARY", "quantity": 12 }] }
{ "type": "price.update",  "items": [{ "sku": "VC-AN-01-M", "price": 2499, "mrp": 3499 }] }
{ "type": "order.status",  "orderNumber": "VC1712345678901", "erpOrderId": "UJ/26-27/1", "orderStatus": "packed", "note": "…" }
```

Failed events on our side retry automatically (30s → 2m → 10m → 1h → 6h) and ERP downtime never
blocks website checkout — orders queue as `erpSyncStatus: pending` and sync later.

## 4. If there is no API — acceptable alternatives

1. **Scheduled CSV/Excel exchange:** ERP exports item master + stock (hourly/daily) to an agreed
   location (SFTP/Drive/email); website exports confirmed orders in your import format.
2. **Read-only database + sync agent:** a small read-only SQL user on the ERP database, with a
   lightweight sync program on the shop PC pushing changes to our server every 15 minutes.
Either is acceptable as Phase 1 while a full API is prepared. Please tell us which you can support
and share one sample file/query output for each of: item master, stock, sales order import.
